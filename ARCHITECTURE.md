# techne — repo card

WHAT: local-first, single-SQLite-file persistent memory for AI coding agents (mainly Claude Code). Captures sessions/threads/observations, curates durable knowledge, self-maintains (reflect/consolidate/dream) on the agent's OWN model — no API key.
STATE: main, v0.17.0, Alpha, active (the provenance pass — 0.16.x went after what the instruments ASSERT, from a row's kind to a call graph's unresolved edges to the faults fsck gave you no way to clear; this one went after where a row CAME FROM and whether a claim about it can be checked. `knowledge.last_confirmed_at` was `NOT NULL DEFAULT CURRENT_TIMESTAMP` on a fresh install and plain nullable on a migrated one at the SAME `schema_version`, so a store's provenance changed its retrieval order; `checks_green` gives a lint or type-check claim a shape the evidence gate can verify — for ruff/mypy/pyright, the rest resolve `unverifiable` — and that gate now covers state claims and not only deeds; `--version` reported a number that could have been any build and now names the sha it was installed from; a `table="all"` page reserves up to three head slots for the best curated rows, where the vector channel used to be able to take the whole head; `per_turn_recall_chars` stopped being capped at 500 behind the operator's back and now records what it dropped. Plus the half that reaches a user: the SessionStart banner reports codex and arch-card staleness instead of leaving it to be discovered, and `doctor` no longer names commands that do not exist. One finding reaches no user but changes how we measure: the #883 paraphrase curve was tracking vocabulary, not corpus size).
STACK: Python 3.11+ (CI 3.12/3.13 matrix + a separate 3.14 `eval-vec` arm), Click CLI, stdlib sqlite3 (WAL) = sole store. Optional extras: `[vectors]` (sqlite-vec + fastembed/model2vec, semantic search), `[codex]` (tree-sitter code graph), `[llm]` (litellm, headless passes), `[security]`, `[watch]`, `[recommended]` = vectors+security. Install from git: `pipx install "techne[recommended] @ git+https://github.com/tenishai/techne.git@v0.17.0"` — PyPI `techne` is an UNRELATED package. stdio MCP server. Dockerfile present.

HEALTH: green. 130 test files (`tests/**/test_*.py`); CI pytest on 3.12/3.13 every push/PR, run PARALLEL under pytest-xdist, worker count PINNED at `-n 4` not `auto` (#463 — the suite is syscall-heavy and was 97.5% of every job; note that is kernel CPU, not I/O wait, so the ceiling is core count: ~2x on the 2-core runner vs ~4x on a 6-core laptop. `ci-local.sh` uses `-n auto` on purpose — worker count provably does not change outcomes) (ruff runs too but is ADVISORY — `|| true`, so lint never fails the build), plus the deterministic eval gates (#68 recall, #385 retrieval-correctness) and the 3.14 `eval-vec` arm (#399), both left SERIAL on purpose (each selects a handful of tests; eval-vec also uses `-s`, which xdist does not support), the `arch-cards` freshness gate (#383), and the `crash-recovery` fault-injection gate (#388 — `-m crash`, SERIAL and `-p no:randomly`: it spawns subprocesses that SIGKILL themselves mid-write against a shared on-disk store, so a random order that flaked would teach people to re-run CI, which is how a real regression gets waved through). THE `crash` MARKER IS THE COVERED CASE, NOT THE UNCOVERED ONE — it is excluded from the default run like `eval`/`eval_gate`/`eval_vec` AND run by a dedicated job, which is exactly the distinction the DELIBERATELY LOCAL-ONLY block below turns on. CHANGELOG's most recent released section is [0.15.0]; [Unreleased] is empty at the cut.
DELIBERATELY LOCAL-ONLY — THREE THINGS CI DOES NOT COVER, BY DECISION (#453, #537; Richard, 2026-08-07; #883 added a fourth and #945 took most of it back — `eval_scale` is a CI job now, and only its real-content arm stays local). This is a standing policy, not a backlog item: each needs a toolchain CI is not going to carry, and each would SKIP rather than fail if wired up naively, so the cost of covering them is a green result that means less than it looks.
- `probe` (3 tests, #94 memory-attribution) — spawns a real agent session; needs the `claude` or `opencode` CLI on PATH.
- `eval_llm` (1 test, #118 Stage 2) — needs a reachable model.
- `eval_scale`'s REAL-CONTENT ARM (1 test of 5, #945) — `test_real_content_crowds_harder` borrows rows from `~/.techne/techne.db` to use as distractors, so it needs a store CI does not have and skips cleanly without one. Read-only BY CONSTRUCTION: a `mode=ro` URI, never `connect()`, which would run the migration ladder against the operator's live store. The rows are private memory — they enter a `tmp_path` database as distractors only, are never committed, never queried against, and never printed; the queries and gold stay the committed set, so what the arm emits is a score, not content. THE OTHER FOUR ARMS NOW RUN IN CI: `eval_scale` is invoked by the `eval-vec` job (#945, closing half of #895), which already installs sqlite-vec and the cached model2vec — measured 38.8s for all five arms at the default n=2,000 against that job's own ~30s gate. Still INFORMATIONAL wherever it runs: every arm asserts its INSTRUMENT, never a result — that the padding is present, distinct, embedded, and that the two channels genuinely differ — so no score can fail a build.
  WHAT THE ARMS ESTABLISHED, and it reverses how the #883 curve should be read. The curve itself: paraphrase recall@10 is 1.0 at the 36-row corpus `eval_gate`/`eval_vec` use, 0.667 at n≈2,000 and 0.5 at n≈4,000, while exact/filter/negative do not move and fpr stays 0.000 — so those gates vouch for a capability they have only ever measured where it cannot fail. #945 then varied the padding VOCABULARY with everything else held identical: a disjoint domain scores **1.000 at both n≈2,000 and n≈4,000**, with both corpora embedding the same number of rows (asserted, because padding missing from the vector index would also score 1.000 and look the same). So the degradation is semantic adjacency between the distractors and the gold, NOT corpus size — at the sizes this harness reaches, scale alone costs nothing. Real rows borrowed from the live store score **0.167** where the synthetic near padding scores 0.667, so both synthetic arms understate production by roughly 4x. NO PARAPHRASE FLOOR IS SET, and #945 is the measurement saying why rather than an absence of one: a floor off the near arm would encode this project's vocabulary as a property of the retriever, a floor off the far arm would be 1.000, and the only arm resembling production cannot be committed because it differs per machine.
  The two above are excluded from the default run by `pyproject.toml:addopts` AND invoked by no workflow. Contrast `eval`/`eval_gate`/`eval_vec`/`eval_scale`, also excluded from the default run but each RUN by a dedicated CI job — exclusion alone does not tell you which case you are in.
- `RUN_LSP_INTEGRATION` (2 tests, in `test_codex_lsp_resolve.py` and `test_lsp_client.py`) — needs `pyright-langserver`, i.e. a Node toolchain for two tests. The env var appears in no workflow and no doc; setting it is a local opt-in. NOTE the files themselves are NOT skipped — they hold 11 tests and the other 9 run normally in CI; it is 2 tests inside them that are gated.
**A green build does not cover any of these.** Run them locally when touching #94 attribution, the LLM-judged eval, LSP edge resolution, or anything that changes retrieval ranking or the embedding backend (the scale arm is the only thing that measures retrieval at a corpus size where it can fail). `tests/test_local_only_suites.py` fails if this list and the repo stop agreeing.
