# sync-adapters — egress + ingest protocols

SEAM: two runtime_checkable Protocols:
- SyncAdapter: push(entries)→PushResult, pull(query)→list[KnowledgeEntry], health() — OUTBOUND team-backend sync.
- SourceAdapter: initial_walk(), start_watch(), stop_watch(), health() — INBOUND ingest (observations; CCMemorySource drains curated_memory). Optional `provides:{'curated','raw'}` attr for the #107 reconciler.
IMPLS: built-in noop (sync/noop.py), filesystem (sync/filesystem.py). Also: cc_memory, github_issues, jsonl_records, jsonl_transcript, sinks, outbox.
OPS: load_adapter(name, *, allow_unlisted=False, **kwargs) — built-ins first, then 3rd-party via `techne.sync_adapters` entry-point group (pyproject registers noop, filesystem); unset kwargs dropped so minimal adapters keep a no-arg __init__.
DEFAULT-DENY ON UNLISTED ADAPTERS (techne#389), AND THE ISSUE'S OWN PREMISE WAS WRONG. #389 asked for a flag refusing to POST to non-local destinations. THERE IS NO SUCH POST: measured 2026-08-17, the package has ZERO network-capable imports — no `requests`, `httpx`, `aiohttp`, `urllib`, `http`, `socket`. Both built-ins are local, the single outbound path is `litellm` in `core/thread_orchestrator.py` (already governed by EGRESS_KEYS: `model`, `reflect.model`, `conflict.model`, `llm_api_base`, `llm_api_key`), and `github_issues` is INGEST via the `gh` CLI. So the boundary that was actually missing is `load_adapter` itself, which would import ANY class registered under the entry-point group and hand it every outbox entry — full session and memory content. A remote shipper does not have to be written by us to exist. The refusal is placed BEFORE `ep.load()` deliberately: `load()` imports the module and import-time side effects are code execution, so a gate after the class is in hand would be cosmetic. Opt-in is `sync.allow_unlisted_adapter` (default False, emitted to YAML only when True so a config.yaml never carries a `false` that reads as a chosen knob). WHAT IT BUYS, STATED HONESTLY: within one OS user this is not a wall — an agent that can rewrite config.yaml can rewrite the venv this code lives in, the same caveat config-trust makes about itself. It buys that an unlisted adapter cannot load SILENTLY: it must be named twice, and under a locked operator layer the operator owns both names, since `sync` is a WHOLE-BLOCK EGRESS_KEYS entry and therefore covers the new sub-key with no extra judgment (see the #588 recursion rule in docs/arch/config-trust.md). Blast radius at landing: ZERO — the only registered entry points were techne's own noop and filesystem. A CALL SITE THAT DOES NOT PASS THE CONFIG VALUE FAILS CLOSED (the parameter defaults False), and a test pins that all three call sites pass `config.sync.allow_unlisted_adapter` rather than a hardcoded True — the #596 shape, where a guard's precondition is the way to switch the guard off.
CONSUMERS: outbox flush (sync/outbox.py), `techne init` (config.sync.adapter), `techne status`.
INVARIANTS:
- PushResult.synced = count of CONSECUTIVE leading successes from batch start — NEVER higher even if a later entry would've succeeded. Partial-middle failure → retry whole-batch-from-failure next flush.
- Namespacing (techne#51): outbox targets `sync:<name>` (adapter-bound) vs `sink:<name>` (sink-bound); enqueue REJECTS un-namespaced targets so the two flush paths never cross-drain.
