# search / embeddings — hybrid FTS + vector recall

WHAT: recall over knowledge/threads/observations = hybrid BM25 (FTS5) + vector (sqlite-vec, vec0). search()/search_vec() in core/search.py; embedding-backend abstraction in core/embeddings.py.
MMR — CODE EXISTS, NO CONFIG SURFACE (techne#420): `_mmr_reorder()` is implemented and `_rerank`/`search_fts` accept `mmr_lambda`, but every live caller leaves it at the `0.0` function default, so ordering stays pure relevance. THE `search.mmr_lambda` CONFIG KNOB WAS REMOVED — it was parsed, defaulted to 0.3 and serialized while reaching no search function, so it read back correctly and did nothing. Re-plumbing it must arrive WITH a measurement, which needs an embedding-backed corpus: `_mmr_reorder` returns `candidates[:limit]` unchanged at four exits — λ=0 (search.py:55), no numpy (:61), no embedding backend (:67), embed raised (:81) — and none of them is reached via `sqlite-vec`, which indexes `search_vec` and does NOT gate this path. The eval gates currently hit the numpy exit, so they cannot observe MMR at any λ.
FUSION (techne#401/#402) — VEC-FIRST UNION, **NOT RRF**: vector hits come first (ascending distance, already sorted by search_vec), then FTS-only hits appended in search_fts's order. A row in BOTH channels keeps its vector position; agreement is recorded as provenance (`match_source: fts+vec`, `fusion: vec_first`), NOT as a rank boost. RRF was REMOVED — the #399 ablation showed its rank-sum buries a strong single-channel (vector-only) hit under lexically-tempting FTS distractors: paraphrase recall@10 0.667 vs 1.0, MRR 0.144 vs 0.546, while only TYING on exact/filter/negative. `_rrf_fuse`/`RRF_K` are deliberately RETAINED in the module as an unused library primitive (the #399 ablation arm + a possible single-channel-floor fallback) — do NOT read their presence as "RRF is live".
BACKEND (techne#601/#602): ONE interface (EmbeddingModel) over TWO backends — fastembed (TextEmbedding, MiniLM-384) OR model2vec (StaticModel, potion-base-8M, 256-dim, numpy-only static). config `search.embedding_backend=''` = AUTO-SELECT (NOT disabled): model2vec on Python 3.14+ or when fastembed is absent, else fastembed.
CONSTRAINT — fastembed is UNUSABLE on Python 3.14: its dep onnxruntime ships no 3.14 wheel. On 3.14 the live backend is model2vec/potion (dim 256). Do NOT try to "enable fastembed" on 3.14 — it cannot load.
CHECK, DON'T ASSUME: the live backend is machine/python-version dependent and `embedding_backend=''` means auto — so read it from `techne vectors status`, never infer it from the (often empty) config value.
DEGRADE: vector search silently falls back to FTS-only when sqlite-vec/the backend is unavailable OR the vec tables are stale after a backend swap. Distances are normalized so model2vec L2 stays comparable to the fastembed baseline (tag_threshold ceiling is backend-dependent: potion tops ~0.59).
BUILD/REPAIR: `techne vectors backfill` embeds un-embedded rows (and does a full drop+re-embed on a backend/model swap via _ensure_vec_backend_identity).
INVARIANT (techne#382, FIXED in #407, schema v19): any path that edits a knowledge row's `content` IN PLACE must set `vec_stale=1`. `connect()` never loads sqlite_vec (techne#168), so the mutation site physically cannot re-embed; `backfill_vectors` reconciles the flag where the extension IS loaded (re-embeds rows missing from *_vec OR carrying vec_stale=1, then clears it). WAS (pre-#407, do not re-derive this from old notes): backfill embedded only rows MISSING from *_vec, so an edited gist kept matching its OLD text forever.
OPERATOR ACTION IS STILL REQUIRED — the flag fixed the MECHANISM, not the need to act: nothing auto-runs `backfill_vectors` in production ("nothing auto-runs backfill_vectors in production today", search.py:897; "never hook-invoked", embeddings.py:45). Its only caller is the `techne vectors backfill` CLI command (cli.py:2877). So a `vec_stale=1` row stays dirty — and semantic recall keeps matching the OLD text — until a human runs backfill.
CONSUMERS: techne_search / recall; the per_turn_recall UserPromptSubmit rail (techne#109, hybrid search over knowledge, top-N injected per turn); Librarian gist recall; reflect/consolidate similarity. First embed triggers a HuggingFace model fetch (model2vec potion / fastembed onnx); uncached + offline degrades rather than crashing.
