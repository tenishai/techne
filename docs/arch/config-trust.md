# config-trust — operator-vs-agent boundary over egress-selecting config (techne#393)

WHAT: a second config file, owned by someone the agent is not, holding the keys that choose a DESTINATION for memory. techne's MEMORY egress is closed by default (`sync.adapter=noop`, no `llm_api_base`, no connections — the LLM path is NOT closed, see the wording invariant) — but `config.yaml` lives under `techne_home()` and the agent can rewrite it, so before this the door was locked with the key in the agent's pocket.
RESOLUTION (descending authority, first that EXISTS wins): `/etc/techne/config.operator.yaml` → `$TECHNE_OPERATOR_CONFIG` → `<techne_home>/config.operator.yaml`. The system path is checked FIRST and unconditionally. THE THREE TIERS ARE NOT EQUAL IN STRENGTH — see the first invariant.
GATE: `Config._gate_egress`, called only from `Config.load()`. ONE chokepoint, not the five consumers (cli sync push, both session hooks, MCP federation fan-out, thread_orchestrator's litellm call) — a gate a caller can forget is not a gate. Only tests construct via `_from_dict`.
STATES:
  locked   — layer exists, this process cannot rewrite it → its values are authoritative, config.yaml's egress keys are DROPPED (not merged).
  unlocked — layer exists, this process could rewrite it → FAIL CLOSED: neither file trusted, the BUILT-IN DEFAULT destinations stand (not silence — see the wording invariant).
  absent   — no layer → unchanged behavior, config.yaml keeps full authority, `config:trust` reports it.
LOCK PREDICATE (`evaluate_lock`, all must hold): regular file, not a symlink; `st_uid != euid`; not group/world-writable; not writable via ACL/group; and NO ancestor directory writable by us.
EGRESS_KEYS (the governed set): `sync`, `connections`, `llm_api_base`, `llm_api_key`, `model`, `reflect.model`, `conflict.model`, `archivist_db_path`, `standalone`, `stores`. EXPIRY CONDITION: the set is correct today partly by accident of scope — store DSNs are SQLite-only (`load_store` raises otherwise, techne#135). techne#87 (postgres stores) makes a DSN a network destination and obliges a revisit.
CONSUMERS: techne/config.py (`Config.load`, `Config.save`); techne/core/checks.py `check_config_trust` (subsystem `security`, kind FAIL_OPEN).

INVARIANTS:
- **ONLY `/etc/techne/config.operator.yaml` IS A REAL LOCK. The other two tiers are conveniences, and the card previously listed all three as if they were equivalent.** `resolve_operator_config` closes the DANGLING-pointer case (a set-but-wrong `$TECHNE_OPERATOR_CONFIG` is reported, not ignored) but cannot close the UNSET case: `env -u TECHNE_OPERATOR_CONFIG techne ...` — or relocating `TECHNE_HOME`, which `techne_home()` also reads from the environment — falls through to `absent`, and config.yaml regains full authority. So an operator who follows this card's own instruction ("put the layer outside the agent's writable tree"), deploys to /opt, and sees a correct LOCKED verdict still has no boundary against a hostile agent. `check_config_trust` names the tier — three-valued, since the `<techne_home>` tier's lever is `TECHNE_HOME` and not `$TECHNE_OPERATOR_CONFIG` — and names the lever that actually applies to it. **THE WARNING'S SURFACE IS WEAKER THAN "the check warns" SOUNDS, and that is stated here rather than left to be discovered: the verdict is LIVE, so `doctor` prints the warning in the detail column and then, on the same screen, summarises "none failing" — or, on a store with no dormant checks at all, the stronger "All N subsystems confirmed live."; `format_banner` is warnings-only and drops it entirely.** A green summary over a red detail is the shape `health.py` itself names as the bug this work exists to remove. Accepted here because the alternative — failing a supported deployment forever — is the never-green trap this repo has already paid for twice, but the argument for a permissive default rests on honest reporting, and this is exactly how far that reporting reaches. THE VERDICT STAYS LIVE rather than failing, and that is a recorded call, not an oversight: the env tier is a legitimate deployment under a controlled environment (an immutable systemd `Environment=`), and a permanent red on a supported path trains operators to ignore the check. The warning names the exact bypass. (Prudence, PR #508; reproduced before documenting.)
- **A techne RUNNING AS ROOT CAN NEVER HONOR AN OPERATOR LAYER, and the repo's own container is that case.** `euid == 0` short-circuits to `unlocked` before the file is read — correctly, since root can rewrite anything, so no lock is provable and claiming LOCKED would be a lie. But the shipped `Dockerfile` has NO `USER` directive and mounts `/root/.techne`, so an operator who bakes `/etc/techne/config.operator.yaml` into that image gets their pins silently discarded. Give the container a non-root `USER`. The check's remedy branches on this reason, because the generic chown advice cannot clear the euid-0 verdict — a remedy that cannot clear its own finding is the never-green defect this repo has already fixed once.
- **THE ONE-LINE TEST OF THE PRESERVATION FIX, checkable against a future diff: under an enforcing verdict, the egress subset of `config.yaml` is identical before `load()` and after `save()`.** The three regression tests pin exactly that property. WHY IT IS NOT A NEW HOLE, in its strongest form (Prudence's, better than the one first recorded here): the set of egress values on disk after `save()` is exactly the set that was there before `load()`, so `save()` cannot introduce a value the agent had not already written itself — and the agent could write those values directly at any time, gate or no gate. Preservation therefore grants no capability that did not already exist.
- **DECOMMISSIONING A LAYER IS A SECURITY EVENT: removing it RE-ARMS whatever `config.yaml` holds, and `config.yaml` is by construction agent-writable.** This is the operational consequence of the preservation above and it is not obvious. Before the fix, an install might (unreliably, only if someone happened to run `techne init`) have had those values scrubbed. Now they survive by design. READ `config.yaml` BEFORE TAKING A LAYER DOWN.
- **NOT PERSISTING THE OPERATOR'S VALUES AND NOT DESTROYING config.yaml'S OWN ARE DIFFERENT REQUIREMENTS.** The first cut satisfied only the first, and `save()` therefore deleted the agent-side `sync` (including `sync.auth`), `llm_api_key`, `connections`, `stores`, `model`, `standalone` and `archivist_db_path` from config.yaml on the next `techne init` — a load→mutate→save round-trip. Unrecoverable, on a routine command, along the exact path this card names as the expected operator mistake. `capture_egress` snapshots the file's own values before the strip and `save()` replays them, so the file keeps recording what the agent side asked for while the gate goes on ignoring it. A revocation that outlives its cause is the mirror of the privilege that outlives its grantor, and this repo's `save()` already carried two comment-scars from the same shape (#167, #601).
- **THE DEFAULT LOCATION CAN NEVER BE LOCKED, AND THAT IS THE PREDICATE WORKING, NOT FAILING.** `~/.techne/config.operator.yaml` sits under `$HOME`, which the agent's uid can write — so it renames `.techne` aside and supplies its own tree, and every property of the file itself becomes irrelevant. The ancestor walk is what catches this. A deployment that wants a real lock MUST put the layer outside the agent's writable tree; `/etc/techne/` is the intended home. An operator who drops the file next to `config.yaml` gets `unlocked` + a BROKEN check naming the writable parent, which is the honest answer rather than a comfortable one.
- **THE OPERATOR LAYER IS AUTHORITATIVE FOR THE WHOLE SET, AND A KEY IT OMITS REVERTS TO THE BUILT-IN DEFAULT — it does not fall back to config.yaml.** Partial authority is not authority: a layer pinning only `sync` while config.yaml kept `llm_api_base` would read as locked while leaving a destination the agent still picks. The cost is real and deliberate — an operator layer that forgets `standalone` flips it back to `true` — so the layer is a complete statement of destinations, not a patch. **`stores` IS THE WORST CASE AND THE ONE TO WARN ABOUT: a forgotten `standalone` is loud, a forgotten store DSN is SILENT.** `store_path` falls back to `<data_dir>/<domain>.db` and `load_store` defaults to a `SqliteStore`, so an omitted `stores` block does not error — it opens a NEW, EMPTY database, and the operator sees intact-looking domain memory with nothing in it. Release-note item, not just a card line.
- **WITHIN ONE OS USER THERE IS NO BOUNDARY, and the card says so rather than implying one.** An agent that can rewrite `config.yaml` can rewrite the venv this code is imported from. What the gate buys on a same-uid host is that a silent key-flip becomes a fail-closed and visible one. It becomes a wall only when the deployment gives the agent its own uid (the one-install-per-agent target), where `st_uid != euid` is enforced by the kernel instead of by politeness.
- **`unlocked` IS THE ONLY ALARMING STATE, AND A NAIVE "IS EGRESS CLOSED?" CHECK WOULD RENDER IT GREEN** — because the keys such a check reads (`sync.adapter`, `llm_api_base`) sit at their built-in values in exactly that state. Closed-by-accident and closed-by-enforcement are different states and only one survives an adversary. `absent` is DORMANT (a single-user install that never deployed a layer is not lying), `locked` is LIVE, `unlocked` is BROKEN: someone intended a boundary and does not have one.
- **THE CHECK PROBES THE FILESYSTEM LIVE AND DOES NOT READ `config.egress_trust` AS ITS PRIMARY SIGNAL.** The first cut did, and a `Config` built by direct construction carries no verdict, so it answered UNKNOWN — a check whose result depends on how its INPUT WAS CONSTRUCTED measures its caller, not the subsystem (it took the health banner amber across five unrelated tests). The recorded verdict is consulted for one thing only: disagreement with the live probe, which means a layer was deployed after this process loaded and the process is still honoring the old resolution — reported STALE, because live-LOCKED alone would be a false green.
- **`save()` NEVER WRITES THE EGRESS SET BACK DOWN while a layer is in force.** `techne init` is a load→save round-trip, so without this the operator's pinned values land in the agent-writable file, where they read as authoritative AND keep applying if the layer is later removed. A privilege that outlives the thing that granted it is not a boundary. Applies to `unlocked` too.
- SCOPE IS DESTINATION, NOT VOLUME. `threads.detector='llm'` and `reflect.enabled` increase traffic to the endpoint but cannot change which endpoint it is, because every endpoint-selecting key is in the governed set. Statable guarantee: under a locked layer an agent can make techne talk MORE, never talk somewhere NEW.
- **THE PREDICATE PROVES A RESOLVED PATH; THE READER MUST OPEN THAT SAME INODE.** The ancestor walk covers BOTH the unresolved and resolved chains, and `TrustVerdict.read_target` carries the resolved path. Walking only the resolved chain was a real hole: given `/agent/link → /etc/techne` with `/agent` writable by us, `lstat` follows the intermediate symlink to the genuine root-owned file and `resolve()` yields root-owned ancestors → LOCKED, while the directory that actually decides where the later `open()` lands was never inspected. Reproduced, then fixed.
- **SAY "BUILT-IN DEFAULT DESTINATIONS", NEVER "CLOSED DEFAULTS".** `model` defaults to `claude-haiku-4-5-20251001` and, with `llm_api_base`/`llm_api_key` empty, litellm falls back to env-var provider routing — so an enforcing verdict still makes outbound LLM calls. The guarantee is that the agent cannot REPOINT that traffic, not that nothing leaves. "Closed" reads as "no traffic" to an operator, and that is false.
- **THE PERMISSIVE `absent` DEFAULT IS BACKED BY A DOCTOR-ONLY SIGNAL.** `absent` is DORMANT, DORMANT ties with LIVE, and `format_banner` is warnings-only — so "this install's egress selector is agent-writable" reaches only an operator who runs `techne doctor`. That is uniform with every other DORMANT check and is not changed here, but the argument for permissive-by-default rests on the state being reported honestly, and this is the surface where it is reported.
- A malformed operator layer parses to `{}` and therefore grants nothing — fail closed — while still reporting as present, so it never reads as `absent`.
